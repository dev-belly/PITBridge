# PITBridge v0.2.0

This release packages the work since v0.1.0 into an installable, checked snapshot.
Python 3.11+ is required, with no third-party runtime dependencies.

- Import scalar and rolling CSV tables through `build --csv-dir` and
  `aggregate --csv-dir`, or call `load_csv_inputs` from Python. Headers, quoting,
  field counts, exact integer revisions and domain rules are validated before
  writing reports. pandas remains optional for the separate DataFrame example.
- Compute availability-aware rolling sums, observation means and counts, retaining
  contributing record revisions and independently replaying membership and values.
- Run the isolated-process `benchmark` command; saved 100,000/1,000,000-row
  measurements include workload, source digests, environment and oracle scope.
- Preserve CR/LF, NUL and Unicode identities in browser selectors; neutralize
  formula-like string exports with a visible, collision-safe `text: ` prefix.
  Source identities remain unchanged in normalized JSON inputs.
- Reject out-of-range UTC timestamps, overflowing/invalid windows and malformed
  CSV input with diagnostics. Linux and Windows checks include clean wheel
  installation and semantic replay outside the source checkout.

## Install

```bash
python -m pip install "https://github.com/dev-belly/PITBridge/releases/download/v0.2.0/pitbridge-0.2.0-py3-none-any.whl"
python -m pitbridge demo --out outputs
python -m pitbridge verify --out outputs
```

The release has five assets: wheel, source distribution, `installed-check.json`,
`release-manifest.json` and `CHECKSUMS.sha256`. The manifest records the exact
successful main CI commit. The published wheel is the same wheel installed and
replayed in CI. The full CI must succeed, including Windows, optional pandas
and real Chrome selector checks. See [the release procedure](../RELEASING.md).

## Upgrade and saved evidence

Package version `0.2.0` is separate from bundle format markers. Scalar manifests
retain the legacy `pitbridge/0.1.0` marker; rolling manifests retain
`pitbridge/rolling/1`. These markers do not identify the installed package version.
The public scalar API and input field names remain available.

Semantic replay compares report bytes as well as numerical artifacts. Earlier
rolling HTML used a different selector encoding, so regenerate old rolling
bundles from their retained `inputs.json` using `aggregate --inputs`. Scalar
bundles with formula-like string identities may also need regeneration using
`build --inputs` because the CSV export policy changed. Old ordinary scalar
identities can still replay, but there is no promise of arbitrary old HTML byte
compatibility. Keep the original bundle and source revision before migrating;
use a new output directory. The committed default bundles replay under v0.2.0.

These checks demonstrate temporal selection and deterministic research evidence.
They do not authenticate upstream availability timestamps, establish complete
source coverage, or turn binary64 features into exact monetary accounting.
