# PITBridge v0.2.1

The checked wheel includes the decision-time precision repair already merged
into the source. A seventh fractional-second digit could previously be silently
discarded, making a source record that arrived just after a decision appear
available at the cutoff. Timestamps finer than microseconds now fail before
selection or report creation, including trailing zero digits.

```bash
python -m pip install "https://github.com/dev-belly/PITBridge/releases/download/v0.2.1/pitbridge-0.2.1-py3-none-any.whl"
python -m pitbridge demo --out outputs
python -m pitbridge verify --out outputs
```

Python 3.11+ is required; the wheel has no third-party runtime dependencies.
The installed-package check verifies scalar and rolling selection at the cutoff
and one supported microsecond later. It exercises JSON and CSV inputs for both
commands and requires exit 2, a useful diagnostic and no output directory for
an unsupported seventh digit. The release gate requires this evidence alongside
the existing independent replay and benchmark checks.

Fractional seconds on shortened clock forms and fractional-second timezone
offsets also fail explicitly. Standard timezone-aware timestamps with up to
six digits and whole-second offsets retain their existing interpretation.
Existing supported-format demo evidence remains verifiable.

The old v0.2.0 wheel remains available unchanged. If old input timestamps were
already normalized, discarded digits cannot be reconstructed from a saved
bundle. Keep the original source records and rebuild affected cases under a
documented upstream precision policy before relying on their historical
selections. Package version numbers are separate from the existing bundle
format markers; this release does not claim source timestamp authenticity.
